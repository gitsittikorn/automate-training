ติดตั้งและใช้งาน Allure Report

ติดตั้ง Allure Report สำหรับ Playwright ตั้งแต่ตรวจสอบเครื่องมือ ไปจนถึงเปิดดูผล Test พร้อม Screenshot, Video และ Trace

1

ตรวจสอบ Node.js และ pnpm

ยืนยันว่าเครื่องมีเครื่องมือที่ต้องใช้ก่อนเริ่มติดตั้ง Allure

เปิด VS Code → เมนู Terminal → New Terminal และใช้ PowerShell Terminal ที่เปิดอยู่ภายในโฟลเดอร์ Project

เริ่มจากตรวจสอบ Node.js ด้วยคำสั่ง:

node --version
ความหมายของภาพ: Terminal แสดง v24.21.0 หมายถึงเครื่องสามารถเรียกใช้ Node.js ได้แล้ว เลข Version ของแต่ละเครื่องอาจไม่เท่ากัน

จากนั้นตรวจสอบ pnpm ด้วยคำสั่ง:

pnpm --version
ความหมายของภาพ: Terminal แสดง 10.20.0 หมายถึง pnpm พร้อมใช้งานแล้ว เราจะใช้ pnpm สำหรับติดตั้ง Package ในหัวข้อนี้
2

ติดตั้ง Allure CLI

ติดตั้งคำสั่ง allure ให้สามารถเรียกใช้จาก Terminal ได้

ที่ PowerShell Terminal ใน VS Code รันคำสั่ง:

pnpm add -g allure
ความหมายของภาพ: บรรทัด + allure 3.20.1 และ Done หมายถึงติดตั้ง Allure CLI สำเร็จแล้ว
ถ้าเห็น WARN ไม่ต้องตกใจ: ข้อความ Tarball download average speed... ในภาพเป็นเพียงคำเตือนว่าดาวน์โหลด Package ช้า ไม่ใช่ Error การติดตั้งยังสำเร็จได้ตามปกติ
3

ตรวจสอบว่า Allure CLI ใช้งานได้

ทดสอบคำสั่ง Allure หลังติดตั้งก่อนเชื่อมต่อกับ Playwright
allure --version
ความหมายของภาพ: Terminal แสดง 3.20.1 หมายถึงคำสั่ง allure สามารถใช้งานได้เรียบร้อยแล้ว
4

ติดตั้ง Package สำหรับ Allure ใน Project

ติดตั้งตัวเชื่อม Playwright กับ Allure และ Library สำหรับเพิ่มข้อมูล เช่น Severity

ขั้นตอนนี้ใช้ PowerShell Terminal ใน VS Code และต้องอยู่ในโฟลเดอร์ Project เช่น C:\TQM\all-automate\automate-training

4.1 ติดตั้ง allure-playwright

allure-playwright คือ Package ที่ทำหน้าที่ส่งผลการ Run จาก Playwright ไปสร้างข้อมูลในโฟลเดอร์ allure-results

pnpm add -D allure-playwright
ความหมายของภาพ: ใต้หัวข้อ devDependencies มี allure-playwright และขั้นตอนจบด้วย Done หมายถึงติดตั้งตัวเชื่อม Playwright กับ Allure สำเร็จแล้ว
ถ้าเห็น WARN ไม่ต้องตกใจ: ข้อความ installed by a different package manager หมายถึง Project นี้เคยติดตั้ง Package ด้วย package manager อื่นมาก่อน ไม่ใช่ Error ของ Allure หากจบด้วย Done สามารถทำขั้นต่อไปได้

4.2 ติดตั้ง allure-js-commons

allure-js-commons คือ Library ที่ใช้เพิ่มข้อมูลให้ Test Case เช่น Severity, Feature, Story หรือ Label ต่าง ๆ ใน Allure Report

pnpm add -D allure-js-commons
ความหมายของภาพ: Terminal แสดง + allure-js-commons 3.13.0 และ Done หมายถึง Library สำหรับเพิ่มข้อมูลให้ Allure Test Case ถูกติดตั้งแล้ว
จำง่าย ๆ:
allure-playwright = ตัวเชื่อม Playwright → Allure
allure-js-commons = เครื่องมือสำหรับใส่ข้อมูลเพิ่มให้ Test เช่น Severity
5

ตรวจสอบ Package ที่ติดตั้งใน Project

ตรวจสอบว่า Package ที่ต้องใช้ถูกติดตั้งครบก่อนแก้ Code
pnpm list --depth=0
ความหมายของภาพ: ใน devDependencies ควรเห็นอย่างน้อย @playwright/test, allure-playwright และ allure-js-commons แสดงว่าเครื่องมือสำหรับ Run Test, สร้าง Allure Results และกำหนด Severity พร้อมใช้งานแล้ว
สำหรับผู้เรียน: ไม่ต้องกังวลหากเลข Version ไม่ตรงกับภาพ ตัวเลขอาจเปลี่ยนตามวันที่ติดตั้ง ขอเพียง Package ทั้ง 3 รายการแสดงอยู่และไม่มี Error
✓ SETUP COMPLETE — เตรียม Allure เสร็จเรียบร้อย
เมื่อเห็น @playwright/test, allure-playwright และ allure-js-commons ในรายการ Package แสดงว่าเครื่องพร้อมสำหรับ Workshop แล้ว
ให้หยุดการเตรียมเครื่องไว้ที่ขั้นตอน 5 ขั้นตอนถัดไปจะเป็นการตั้งค่าและใช้งานจริงพร้อมผู้สอน

6

เพิ่ม Allure Reporter ใน playwright.config.ts

บอก Playwright ให้สร้างข้อมูลสำหรับ Allure ทุกครั้งที่ Run Test

ใน VS Code Explorer คลิกไฟล์ playwright.config.ts จากนั้นหา บรรทัดที่ตั้งค่า reporter ใกล้ด้านบนของไฟล์

จุดที่ต้อง Focus: จากภาพตัวอย่าง ให้ดูประมาณ บรรทัด 4–7 โดยเพิ่ม ['allure-playwright'] ต่อจาก HTML Reporter และต้องมีเครื่องหมาย comma หลังรายการ HTML Reporter
reporter: [
  ['html', { open: 'always' }],
  ['allure-playwright']
],
ความหมายของภาพ: ['html', { open: 'always' }] ใช้สร้าง Playwright HTML Report ส่วน ['allure-playwright'] ใช้สร้างข้อมูลให้ Allure ดังนั้น Run Test ครั้งเดียวสามารถได้ผลสำหรับ Report ทั้งสองแบบ
7

จัดกลุ่ม Test Case ด้วย Severity

กำหนดระดับความสำคัญของแต่ละ Test เพื่อให้ Allure Report แยกกลุ่มและกรองผลได้ง่าย

ใน VS Code Explorer เปิดไฟล์ Test เช่น tests/example.spec.ts แล้วเพิ่ม Import และ Severity ให้แต่ละ Test Case

จุดที่ต้อง Focus จากภาพ:
① เปิดไฟล์ tests/example.spec.ts
② เพิ่ม Import allure-js-commons บริเวณด้านบนของไฟล์
③ Test Case has title กำหนดเป็น critical
④ Test Case get started link กำหนดเป็น normal

เพิ่ม Import ด้านบนของไฟล์:

import * as allure from 'allure-js-commons';

ตัวอย่างกำหนด Severity ให้ Test Case:

// npx playwright test tests/example.spec.ts --headed
import { test, expect } from '@playwright/test';
// import เครื่องมือ test และ expect จาก Playwright
// test ใช้สำหรับสร้าง Test Case
// expect ใช้สำหรับตรวจสอบว่าผลลัพธ์ที่ได้ ตรงตามที่คาดหวังหรือไม่
import * as allure from 'allure-js-commons';

test('has title', async ({ page }) => {
  await allure.severity('critical');

  // สร้าง Test Case ชื่อ "has title"
  // page คือหน้า Browser ที่ Playwright เปิดให้เราใช้งาน

  await page.goto('https://playwright.dev/bugs');
  // เปิดเว็บไซต์ https://playwright.dev/bugs

  await expect(page).toHaveTitle(/Playwright bugs/);
  // ตรวจสอบว่า Title ของหน้าเว็บ
  // มีคำว่า "Playwright bugs" อยู่หรือไม่
});

test('get started link', async ({ page }) => {
  await allure.severity('normal');

  // สร้าง Test Case ชื่อ "get started link"

  await page.goto('https://playwright.dev/');
  // เปิดเว็บไซต์ https://playwright.dev/

  await page.getByRole('link', { name: 'Get started' }).click();
  // ค้นหาลิงก์ที่มีชื่อว่า "Get started"
  // แล้วสั่งคลิก

  await expect(
    page.getByRole('heading', { name: 'Installation' })
  ).toBeVisible();
  // ตรวจสอบว่าหลังจากคลิกแล้ว
  // มีหัวข้อ "Installation" แสดงอยู่บนหน้าเว็บ
});
สำหรับ Workshop: ให้เปิดไฟล์ tests/example.spec.ts ใน VS Code แล้วแทนที่โค้ดเดิมในไฟล์ด้วยโค้ดเต็มจากกล่องด้านบน จากนั้นกด Ctrl + S เพื่อบันทึกไฟล์ ผู้เรียนจึงไม่ต้องหาว่าแต่ละบรรทัดต้องนำไปวางตรงตำแหน่งใด
จุดที่เพิ่มสำหรับ Allure มี 3 ส่วน:
1) import * as allure from 'allure-js-commons'; เพื่อเรียกใช้คำสั่งของ Allure
2) await allure.severity('critical'); กำหนด Test Case has title เป็นระดับ Critical
3) await allure.severity('normal'); กำหนด Test Case get started link เป็นระดับ Normal
Severity คืออะไร: เป็นระดับความสำคัญของ Test Case ใช้ช่วยจัดกลุ่มและกรองผลใน Allure Report เช่น Test สำคัญมากอาจกำหนดเป็น critical ส่วน Test ทั่วไปอาจใช้ normal

คำสั่ง Severity ที่ใช้ได้

เลือกใช้ เพียง 1 ค่า ต่อ Test Case ตามระดับความสำคัญของ Test นั้น

await allure.severity('blocker');
await allure.severity('critical');
await allure.severity('normal');
await allure.severity('minor');
await allure.severity('trivial');
ความหมายแบบง่าย:
blocker = ปัญหารุนแรงมากจนงานหลักไปต่อไม่ได้
critical = ฟังก์ชันสำคัญมาก ควรให้ความสำคัญสูง
normal = Test ทั่วไป
minor = ความสำคัญต่ำกว่า Test ทั่วไป
trivial = เรื่องเล็กน้อย ผลกระทบน้อย
ตัวอย่าง: ถ้า Test Case เป็นขั้นตอนสำคัญของระบบ ให้ใส่ await allure.severity('critical'); ไว้ด้านใน Test Case ใกล้บรรทัดแรกหลัง test(...) เพื่อให้หาและแก้ไขได้ง่าย
สำหรับ Training นี้: ใช้เพียง critical และ normal ก่อน เพื่อให้เห็นความแตกต่างของการจัดกลุ่มโดยไม่เพิ่มความซับซ้อนมากเกินไป
8

Run Playwright Test เพื่อสร้างข้อมูล Allure

รัน Test หลังตั้งค่า Reporter เพื่อให้ Allure ได้รับผลการทดสอบ

ในคู่มือนี้ใช้ pnpm เป็นหลัก ให้รัน Test ด้วยคำสั่งด้านล่าง:

pnpm playwright test tests/example.spec.ts --headed
คำสั่งนี้ทำอะไร: tests/example.spec.ts คือไฟล์ Test ที่ต้องการรัน และ --headed คือให้เปิด Browser ให้เห็นระหว่าง Test ทำงาน
หมายเหตุเกี่ยวกับภาพ: ภาพตัวอย่างเดิมแสดงคำสั่ง npx playwright test ... แต่ Training นี้กำหนดให้ใช้ pnpm ดังนั้นให้ผู้เรียนคัดลอกคำสั่ง pnpm playwright test ... จากกล่องด้านบน
ความหมายของภาพ: ข้อความ 2 passed หมายถึง Test ผ่าน 2 Test Case หลังจากจบรอบนี้ Playwright จะสร้างข้อมูล Allure ตาม Reporter ที่ตั้งค่าไว้
9

ตรวจสอบโฟลเดอร์ allure-results

ยืนยันว่ามีข้อมูลดิบสำหรับใช้สร้าง Allure Report

กลับมาที่ VS Code Explorer แล้วดูบริเวณโฟลเดอร์หลักของ Project ควรพบโฟลเดอร์ allure-results

ความหมายของภาพ: การมีโฟลเดอร์ allure-results แสดงว่า allure-playwright ทำงานและบันทึกผล Test สำเร็จแล้ว โฟลเดอร์นี้เป็นข้อมูลต้นทางที่ Allure ใช้สร้างหน้า Report
10

เปิด Allure Report

นำข้อมูลใน allure-results มาเปิดเป็นหน้า Report บน Browser

กลับไปที่ PowerShell Terminal ใน VS Code แล้วรัน:

allure serve allure-results
ความหมายของภาพ: ข้อความ Allure is running on http://localhost:... หมายถึง Allure Report เปิดเป็น Web Server ในเครื่องแล้ว Browser จะเปิดหน้า Report ให้ใช้งาน
สำคัญ: เลข Port เช่น 60938 อาจเปลี่ยนทุกครั้ง ไม่จำเป็นต้องได้เลขเดียวกับในภาพ และให้เปิด Terminal นี้ค้างไว้ระหว่างดู Report
11

อ่านผล Test ใน Allure Report

ดูสถานะ Test และหลักฐานที่ Playwright เก็บไว้จากการรันจริง
ความหมายของภาพ: หน้า Test Case แสดงสถานะ Passed, ระยะเวลา, Labels และลำดับ Test body พร้อมหลักฐาน เช่น Playwright Trace, Screenshot และ Video หาก Project ตั้งค่าให้เก็บข้อมูลเหล่านี้ไว้

ส่วนนี้เหมาะสำหรับตรวจสอบว่า Test ทำอะไรไปบ้าง และใช้ข้อมูล Screenshot / Video / Trace ช่วยวิเคราะห์เมื่อ Test Fail

ความหมายของภาพ: หน้า Graphs ใช้ดูภาพรวมของผล Test เช่นกราฟ Current status แสดงสัดส่วน Passed / Failed และกราฟ Test results by severities แสดงจำนวน Test แยกตาม Severity
ถ้าเห็น No history information available หรือ No results: หมายถึงกราฟนั้นต้องใช้ข้อมูลย้อนหลังหรือ Label เพิ่มเติมที่ยังไม่ได้ตั้งค่า ไม่ได้หมายความว่า Allure ติดตั้งผิด

กรอง Test ตาม Severity

ที่หน้า Results คลิกตัวกรอง Severity แล้วเลือกค่าที่ต้องการ เช่น Critical และ Normal เพื่อแสดงเฉพาะ Test Case ในกลุ่มนั้น

ความหมายของภาพ: Allure Report สามารถใช้ Severity เป็นตัวกรองได้ ทำให้ผู้ใช้เลือกดูเฉพาะ Test ที่มีความสำคัญระดับที่ต้องการ เช่น Critical หรือ Normal โดยไม่ต้องไล่ดู Test ทั้งหมดทีละรายการ
ติดตั้งและทดสอบ Allure Report สำเร็จ
เมื่อมาถึงขั้นนี้ ผู้ใช้สามารถ Run Playwright Test → ได้ allure-results → เปิด Report ด้วย allure serve allure-results และดูรายละเอียด Test บน Browser ได้แล้ว
