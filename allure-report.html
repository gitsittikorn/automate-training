ติดตั้งและใช้งาน Allure Report

ติดตั้ง Allure Report สำหรับ Playwright ตั้งแต่ตรวจสอบเครื่องมือ ไปจนถึงเปิดดูผล Test พร้อม Screenshot, Video และ Trace

1

ตรวจสอบ Node.js และ pnpm

ยืนยันว่าเครื่องมีเครื่องมือที่ต้องใช้ก่อนเริ่มติดตั้ง Allure

เปิด VS Code → เมนู Terminal → New Terminal และใช้ PowerShell Terminal ที่เปิดอยู่ภายในโฟลเดอร์ Project

เริ่มจากตรวจสอบ Node.js ด้วยคำสั่ง:

node --version
ความหมายของภาพ: Terminal แสดง v24.21.0 หมายถึงเครื่องสามารถเรียกใช้ Node.js ได้แล้ว เลข Version ของแต่ละเครื่องอาจไม่เท่ากัน

จากนั้นตรวจสอบ pnpm ด้วยคำสั่ง:

pnpm --version
ความหมายของภาพ: Terminal แสดง 10.20.0 หมายถึง pnpm พร้อมใช้งานแล้ว เราจะใช้ pnpm สำหรับติดตั้ง Package ในหัวข้อนี้
2

ติดตั้ง Allure CLI

ติดตั้งคำสั่ง allure ให้สามารถเรียกใช้จาก Terminal ได้

ที่ PowerShell Terminal ใน VS Code รันคำสั่ง:

pnpm add -g allure
ความหมายของภาพ: บรรทัด + allure 3.20.1 และ Done หมายถึงติดตั้ง Allure CLI สำเร็จแล้ว
ถ้าเห็น WARN ไม่ต้องตกใจ: ข้อความ Tarball download average speed... ในภาพเป็นเพียงคำเตือนว่าดาวน์โหลด Package ช้า ไม่ใช่ Error การติดตั้งยังสำเร็จได้ตามปกติ
3

ตรวจสอบว่า Allure CLI ใช้งานได้

ทดสอบคำสั่ง Allure หลังติดตั้งก่อนเชื่อมต่อกับ Playwright
allure --version
ความหมายของภาพ: Terminal แสดง 3.20.1 หมายถึงคำสั่ง allure สามารถใช้งานได้เรียบร้อยแล้ว
4

ติดตั้ง Package สำหรับ Allure ใน Project

ติดตั้งตัวเชื่อม Playwright กับ Allure และ Library สำหรับเพิ่มข้อมูล เช่น Severity

ขั้นตอนนี้ใช้ PowerShell Terminal ใน VS Code และต้องอยู่ในโฟลเดอร์ Project เช่น C:\TQM\all-automate\automate-training

4.1 ติดตั้ง allure-playwright

allure-playwright คือ Package ที่ทำหน้าที่ส่งผลการ Run จาก Playwright ไปสร้างข้อมูลในโฟลเดอร์ allure-results

pnpm add -D allure-playwright
ความหมายของภาพ: ใต้หัวข้อ devDependencies มี allure-playwright และขั้นตอนจบด้วย Done หมายถึงติดตั้งตัวเชื่อม Playwright กับ Allure สำเร็จแล้ว
ถ้าเห็น WARN ไม่ต้องตกใจ: ข้อความ installed by a different package manager หมายถึง Project นี้เคยติดตั้ง Package ด้วย package manager อื่นมาก่อน ไม่ใช่ Error ของ Allure หากจบด้วย Done สามารถทำขั้นต่อไปได้

4.2 ติดตั้ง allure-js-commons

allure-js-commons คือ Library ที่ใช้เพิ่มข้อมูลให้ Test Case เช่น Severity, Feature, Story หรือ Label ต่าง ๆ ใน Allure Report

pnpm add -D allure-js-commons
ความหมายของภาพ: Terminal แสดง + allure-js-commons 3.13.0 และ Done หมายถึง Library สำหรับเพิ่มข้อมูลให้ Allure Test Case ถูกติดตั้งแล้ว
จำง่าย ๆ:
allure-playwright = ตัวเชื่อม Playwright → Allure
allure-js-commons = เครื่องมือสำหรับใส่ข้อมูลเพิ่มให้ Test เช่น Severity

6

เตรียมไฟล์ตัวอย่างให้เหมือนกัน

ให้ผู้เรียนเริ่ม Workshop จาก example.spec.ts ชุดเดียวกัน เพื่อให้ผลที่เห็นตรงกับเอกสารและลดปัญหาระหว่างเรียน Online

ใน VS Code Explorer เปิดไฟล์ tests/example.spec.ts แล้วเปลี่ยนโค้ดทั้งไฟล์ให้ตรงกับตัวอย่างด้านล่าง

วิธีทำสำหรับผู้เรียน: คลิกในไฟล์ example.spec.ts → กด Ctrl + A → กดปุ่ม คัดลอก ด้านล่าง → Paste ทับโค้ดเดิม → กด Ctrl + S
// pnpm playwright test tests/example.spec.ts --headed
import { test, expect } from '@playwright/test';
// import เครื่องมือ test และ expect จาก Playwright
// test ใช้สำหรับสร้าง Test Case
// expect ใช้สำหรับตรวจสอบว่าผลลัพธ์ที่ได้ ตรงตามที่คาดหวังหรือไม่
import * as allure from 'allure-js-commons';


test('has title', async ({ page }) => {
  await allure.severity('critical');

  // สร้าง Test Case ชื่อ "has title"
  // page คือหน้า Browser ที่ Playwright เปิดให้เราใช้งาน

  await page.goto('https://playwright.dev/');
  // เปิดเว็บไซต์ https://playwright.dev/

  await expect(page).toHaveTitle(/Playwright/);
  // ตรวจสอบว่า Title ของหน้าเว็บ
  // มีคำว่า "Playwright" อยู่หรือไม่
});


test('get started link', async ({ page }) => {
  await allure.severity('normal');

  // สร้าง Test Case ชื่อ "get started link"

  await page.goto('https://playwright.dev/');
  // เปิดเว็บไซต์ https://playwright.dev/

  await page.getByRole('link', { name: 'Get started' }).click();
  // ค้นหาลิงก์ที่มีชื่อว่า "Get started"
  // แล้วสั่งคลิก

  await expect(
    page.getByRole('heading', { name: 'Installation' })
  ).toBeVisible();
  // ตรวจสอบว่าหลังจากคลิกแล้ว
  // มีหัวข้อชื่อ "Installation" แสดงอยู่บนหน้าเว็บ
});
ทำไปเพื่ออะไร: เมื่อทุกคนใช้ไฟล์เริ่มต้นชุดเดียวกัน ผลการ Run, จำนวน Test Case และภาพใน Allure Report จะใกล้เคียงกับคู่มือ ทำให้ผู้สอนช่วยแก้ปัญหาได้ง่ายขึ้น
7

เพิ่ม Allure Reporter ใน playwright.config.ts

บอก Playwright ให้สร้างข้อมูลสำหรับ Allure ทุกครั้งที่ Run Test

ใน VS Code Explorer เปิดไฟล์ playwright.config.ts สำหรับ Training นี้ให้ใช้โค้ดทั้งไฟล์ด้านล่าง เพื่อให้ทุกคนเริ่มจาก Config เดียวกัน

วิธีทำสำหรับผู้เรียน: คลิกในไฟล์ playwright.config.ts → กด Ctrl + A → กดปุ่ม คัดลอก ด้านล่าง → Paste ทับโค้ดเดิม → กด Ctrl + S
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [
    ['html', { open: 'always' }],
    ['allure-playwright']
  ],

  use: {
    headless: false,
    browserName: 'chromium',

    screenshot: 'on',
    video: 'on',
    trace: 'on',
  },
});
ความหมายของ Code: html ใช้สร้าง Playwright HTML Report, allure-playwright ใช้สร้างข้อมูลใน allure-results ส่วน screenshot, video และ trace จะเก็บหลักฐานทุกครั้งที่ Run Test ดังนั้น Run Test ครั้งเดียวจะมีข้อมูลพร้อมสำหรับ Report ทั้งสองแบบ
8

ดู Allure Report แบบปกติเมื่อ Test ผ่าน

เริ่มจาก Run Test ให้ผ่านก่อน เพื่อให้ผู้เรียนเห็น Flow ปกติของ Allure ตั้งแต่ Run Test จนถึงเปิด Report

ลำดับนี้ใช้สำหรับสาธิต Report แบบปกติ โดยยังไม่มี Test Failed ให้ทำตามภาพจากบนลงล่าง

8.1 Run Test

เปิด PowerShell Terminal ใน VS Code แล้วรัน:

pnpm playwright test tests/example.spec.ts --headed
ความหมายของภาพ: Playwright Run Test จากไฟล์ tests/example.spec.ts และผล Test ผ่านทั้งหมด จึงเป็นจุดเริ่มต้นสำหรับดู Allure Report แบบปกติ

8.2 ตรวจสอบโฟลเดอร์ allure-results

ความหมายของภาพ: หลัง Run Test จะมีโฟลเดอร์ allure-results ที่ root ของ Project แสดงว่า allure-playwright บันทึกข้อมูลสำหรับสร้าง Allure Report แล้ว

8.3 เปิด Allure Report

กลับไปที่ PowerShell Terminal ใน VS Code แล้วรัน:

allure serve allure-results
ความหมายของภาพ: ข้อความ Allure is running on http://localhost:... หมายถึง Allure เปิด Report บนเครื่องสำเร็จแล้ว เลข Port อาจเปลี่ยนในแต่ละครั้ง

8.4 ดูรายละเอียด Test Case

ความหมายของภาพ: ในหน้า Test Case สามารถดูสถานะ Passed, Test body, Screenshot, Video และ Trace ที่ Playwright เก็บไว้ ช่วยตรวจสอบหลักฐานของการ Run ได้จากหน้าเดียว

8.5 ดู Graphs ของ Allure

ความหมายของภาพ: หน้า Graphs ช่วยสรุปผล Test ในรูปกราฟ เช่น Current status และระยะเวลาในการ Run ทำให้เห็นภาพรวมได้ง่ายกว่าการไล่ดู Test ทีละรายการ

8.6 Run Test หลาย Browser / Device

ตัวอย่างนี้แสดงลำดับตั้งแต่กำหนด Browser / Device ใน playwright.config.ts ไปจนถึง Run Test และดูผลรวมใน Allure Report

เปิดไฟล์ playwright.config.ts ใน VS Code แล้วใช้ตัวอย่างด้านล่างได้เลย สำหรับ Training นี้ให้ Copy โค้ดทั้งหมดแทนไฟล์เดิม เพื่อให้ทุกคนได้ Config เหมือนกัน

import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  reporter: [
    ['html', { open: 'always' }],
    ['allure-playwright']
  ],

  use: {
    screenshot: 'on',
    video: 'on',
    trace: 'on',
  },

  projects: [
    {
      name: 'chromium',
      use: {
        ...devices['Desktop Chrome'],
      },
    },
    {
      name: 'firefox',
      use: {
        ...devices['Desktop Firefox'],
      },
    },
    {
      name: 'mobile-safari',
      use: {
        ...devices['iPhone 13'],
      },
    },
  ],
});
วิธีทำ: เปิด playwright.config.ts → กด Ctrl + A → Paste โค้ดด้านบน → กด Ctrl + S เพื่อบันทึก
ภาพที่ 1 — ตั้งค่า Browser / Device: ในไฟล์ playwright.config.ts กำหนด Project ที่ต้องการทดสอบ เช่น Chromium, Firefox และ Mobile Safari เพื่อให้ Test Case เดียวกันถูกนำไปรันกับหลาย Browser / Device

จากนั้นเปิด VS Code Terminal (PowerShell) และใช้คำสั่งนี้เพื่อ Run Test:

pnpm playwright test tests/example.spec.ts --headed
ภาพที่ 2 — Run Test: ตัวอย่างมี 2 Test Case และ 3 Project จึงเกิดผลการ Run รวม 6 รายการ เมื่อขึ้น 6 passed หมายถึงทุก Test ผ่านครบทุก Browser / Device ที่กำหนดไว้
ภาพที่ 3 — ดูผลใน Allure Report: Allure รวมผลจากหลาย Browser / Device ไว้ใน Report เดียว ทำให้เห็นจำนวน Test ทั้งหมดและสถานะของแต่ละรายการได้ในหน้าเดียว

8.7 ดู Graphs หลัง Run หลาย Browser / Device

ถ้าเห็น No history information available หรือ No results: กราฟบางชนิดต้องใช้ข้อมูลย้อนหลังหรือ Label เพิ่มเติม ไม่ได้หมายความว่า Allure ติดตั้งผิด สำหรับ Training นี้ให้ Focus ที่กราฟซึ่งมีข้อมูลจากการ Run ปัจจุบันก่อน
9

ตัวอย่าง Allure Report เมื่อ Test Failed

ตั้งใจแก้ Test ให้ Fail เพื่อสาธิตว่า Allure ช่วยดู Error และหลักฐานประกอบได้อย่างไร
ขั้นตอนนี้ตั้งใจทำให้ Test Fail เพื่อใช้สอนเท่านั้น ไม่ใช่ปัญหาจากการติดตั้ง Allure

9.1 แก้ Test ให้เจอ Bug แบบตัวอย่าง

เปิด tests/example.spec.ts ใน VS Code แล้ว Copy โค้ดทั้งหมดด้านล่างไปแทนไฟล์เดิม ตัวอย่างนี้ตั้งใจทำให้ Test Case has title Fail เพื่อใช้สาธิตการอ่าน Error และ Allure Report

// npx playwright test tests/example.spec.ts --headed
import { test, expect } from '@playwright/test';
// import เครื่องมือ test และ expect จาก Playwright
// test ใช้สำหรับสร้าง Test Case
// expect ใช้สำหรับตรวจสอบว่าผลลัพธ์ที่ได้ ตรงตามที่คาดหวังหรือไม่
import * as allure from 'allure-js-commons';


test('has title', async ({ page }) => {
 await allure.severity('critical');

  // สร้าง Test Case ชื่อ "has title"
  // page คือหน้า Browser ที่ Playwright เปิดให้เราใช้งาน

  await page.goto('https://playwright.dev/bugs');
  // เปิดเว็บไซต์ https://playwright.dev/

  await expect(page).toHaveTitle(/Playwright bugs/);
  // ตรวจสอบว่า Title ของหน้าเว็บ
  // มีคำว่า "Playwright" อยู่หรือไม่
});


test('get started link', async ({ page }) => {
await allure.severity('normal');

  // สร้าง Test Case ชื่อ "get started link"

  await page.goto('https://playwright.dev/');

  await expect(
    page.getByRole('heading', { name: 'Installation' })
  ).toBeVisible();

  // มีหัวข้อชื่อ "Installation" แสดงอยู่บนหน้าเว็บ
});
วิธีทำ: เปิด tests/example.spec.ts → กด Ctrl + A → Paste โค้ดด้านบน → กด Ctrl + S
ความหมายของภาพ: ตัวอย่างเปลี่ยน URL ไปที่ https://playwright.dev/bugs และตรวจสอบ Title ที่ไม่ตรงกับหน้าจริง จึงตั้งใจทำให้ Test Fail เพื่อใช้ดู Report กรณีพบปัญหา

9.2 Run Test แล้วดู Error ใน Terminal

pnpm playwright test tests/example.spec.ts --headed
ความหมายของภาพ: Terminal แสดง Expected, Received และตำแหน่งของ Test ที่ Fail ช่วยให้รู้ว่า Assertion ใดไม่ตรงกับผลจริง

9.3 เปิด Allure Report ของรอบที่มี Failed

allure serve allure-results

9.4 ดูสรุป Passed / Failed

ความหมายของภาพ: หน้า Results แสดงจำนวน Test ทั้งหมด จำนวน Failed และ Passed พร้อมรายการ Test ที่มีปัญหา ทำให้เลือกเปิด Test ที่ Fail ได้ทันที

9.5 ดู Graphs เมื่อมี Failed

ความหมายของภาพ: กราฟ Current status เปลี่ยนตามผลจริงของรอบนั้น ทำให้เห็นสัดส่วน Passed / Failed ได้ทันที
10

จัดกลุ่ม Test Case ด้วย Severity

เพิ่มระดับความสำคัญให้ Test เพื่อใช้กรองและวิเคราะห์ผลใน Allure Report ได้ง่ายขึ้น

ใน VS Code Explorer เปิดไฟล์ tests/example.spec.ts แล้วเพิ่ม allure-js-commons และ Severity ให้ Test Case ตามภาพ

จุดที่ต้อง Focus:
① เปิดไฟล์ tests/example.spec.ts
② เพิ่ม import * as allure from 'allure-js-commons';
③ Test has title ใช้ critical
④ Test get started link ใช้ normal
import { test, expect } from '@playwright/test';
import * as allure from 'allure-js-commons';

test('has title', async ({ page }) => {
  await allure.severity('critical');

  await page.goto('https://playwright.dev/bugs');
  await expect(page).toHaveTitle(/Playwright bugs/);
});

test('get started link', async ({ page }) => {
  await allure.severity('normal');

  await page.goto('https://playwright.dev/');
  await page.getByRole('link', { name: 'Get started' }).click();

  await expect(
    page.getByRole('heading', { name: 'Installation' })
  ).toBeVisible();
});
Severity คืออะไร: เป็นระดับความสำคัญของ Test Case เช่น critical สำหรับ Test สำคัญ และ normal สำหรับ Test ทั่วไป

คำสั่ง Severity ที่ใช้ได้

await allure.severity('blocker');
await allure.severity('critical');
await allure.severity('normal');
await allure.severity('minor');
await allure.severity('trivial');

หลัง Run Test และเปิด Allure Report สามารถใช้ตัวกรอง Severity เพื่อเลือกดูเฉพาะ Test ที่ต้องการได้

ความหมายของภาพ: ในหน้า Results เลือก Filter เช่น Critical และ Normal เพื่อแสดงเฉพาะ Test Case ตามระดับความสำคัญที่กำหนดไว้
11

Custom กราฟใน Allure Report

ตัวอย่างการปรับหน้า Graphs ให้เหลือเฉพาะ 3 กราฟที่ต้องการ เพื่อให้ Report อ่านง่ายขึ้น

Allure Report สามารถ Custom การแสดงผลได้หลายส่วน ใน Training นี้จะยกตัวอย่างง่าย ๆ โดยเลือกให้หน้า Graphs แสดงเพียง 3 กราฟ

กราฟที่ใช้:
1) Current status — Passed / Failed ของรอบปัจจุบัน
2) Test results by severities — จำนวน Test แยกตาม Severity
3) Durations histogram — การกระจายของระยะเวลา Run Test

11.1 สร้างไฟล์ Config

ที่ root ของ Project สร้างไฟล์ชื่อ:

allurerc.cjs
ทำไมใช้ .cjs? Config ของ Allure ทำได้หลายรูปแบบ แต่ตัวอย่างนี้ใช้ allurerc.cjs เพราะเหมาะกับผู้เริ่มต้น ใช้ module.exports ได้ตรง ๆ และไม่ต้องเพิ่ม "type": "module" ใน package.json หรือเพิ่ม Package สำหรับ Config

11.2 ใส่ Config สำหรับ 3 กราฟ

module.exports = {
  name: 'Allure Report',
  output: './allure-report',

  plugins: {
    awesome: {
      options: {
        reportName: 'Allure Report',

        charts: [
          {
            type: 'currentStatus',
            title: 'Current status',
          },
          {
            type: 'testResultSeverities',
            title: 'Test results by severities',
          },
          {
            type: 'durations',
            title: 'Durations histogram',
            groupBy: 'none',
          },
        ],
      },
    },
  },
};
อธิบายแบบง่าย: charts คือรายการกราฟที่ต้องการแสดง และลำดับภายใน charts: [ ... ] คือลำดับของกราฟบน Report ถ้าต้องการให้กราฟใดขึ้นก่อน ให้นำรายการของกราฟนั้นขึ้นไปไว้ด้านบน

11.3 เปิด Report ใหม่

allure serve allure-results

11.4 ตรวจสอบผลหลัง Custom

ผลลัพธ์: หน้า Graphs เหลือเฉพาะ Current status, Test results by severities และ Durations histogram ทำให้หน้า Report กระชับและเหมาะกับ Training มากขึ้น
แนวคิดสำคัญ: ผู้เรียนไม่จำเป็นต้องจำ Config ทั้งหมด จุดประสงค์ของตัวอย่างนี้คือให้เห็นว่า Allure Report สามารถ Custom ได้ ทั้งการเลือกกราฟและการจัดลำดับการแสดงผล
